# Spike report: NuGet package signature verification

> Saved by the orchestrator from the spike agent's returned text (the agent's environment didn't allow it to write report files). Content is the agent's, lightly formatted.

Spike definition: [docs/spikes/nuget-signature-verification.md](../../docs/spikes/nuget-signature-verification.md).
Environment: Ubuntu 26.04 (linux-x64), .NET SDK 10.0.203 / runtime 10.0.7, **NuGet.Packaging 7.3.1** (the version inside SDK 10.0.203).
All evidence is in `results/` (re-generated by `run-experiments.sh`). Nothing was run on Windows or macOS.

## Summary

1. **API:** `PackageSignatureVerifier` + three providers (`IntegrityVerificationProvider`, `SignatureTrustAndValidityVerificationProvider`, `AllowListVerificationProvider`) + `SignedPackageVerifierSettings`. `dotnet nuget verify` and restore use the same pieces. All public, all in `NuGet.Packaging`. It works.
2. **The Linux trust store is the main problem.** By default NuGet.Packaging uses .NET's default store (the OpenSSL/Mozilla TLS store on Ubuntu), and it **rejects 3 of 4 nuget.org packages** (NU3018/NU3028/NU3037). It only works with the SDK's *fallback bundle* (`trustedroots/codesignctl.pem` + `timestampctl.pem`). NuGet looks for that bundle **next to `NuGet.Packaging.dll`**, and only if the process calls the public, process-global `X509TrustStore.InitializeForDotNetSdk()`. A runtime-only app doesn't have the bundle, so **our library must ship it** (or the app must). With the bundle in place, every case behaved correctly on Linux. Single-file publish crashes inside NuGet unless `NuGet.Packaging.dll` stays outside the bundle.
3. **Self-signed author certs work without touching any store.** An allow-list entry `{Author, SHA-256 fingerprint, AllowUntrustedRoot=true}` accepts the package; without `AllowUntrustedRoot` it is rejected. `dotnet nuget sign` works on Linux with a self-signed cert (warnings only) and fails with a private-CA-issued cert (PartialChain).
4. **Allowed signers:** NuGet's `<trustedSigners>` model (author cert / repository cert + owners, `allowUntrustedRoot`) fits our needs as-is, and its runtime types (`TrustedSignerAllowListEntry`) can be reused. Owners filtering works: Newtonsoft is accepted with owner `jamesnk`, Humanizer rejected.
5. **Offline:** with no network, verdicts are identical. The only difference is NU3018 "revocation unknown" warnings (because `AllowUnknownRevocation=true`). `RevocationMode.Offline` can be set directly through the settings constructor; the env var only affects NuGet's `Get*Policy()` factories. **But a *hanging* network (black-holed, not refused) costs 120 s per package with online revocation**, and a CancellationToken does not interrupt it. `Offline` takes 136 ms in the same situation.
6. **Unsigned local packages** are reported correctly (`IsSigned=false`, NU3004 when signatures are required). **Tampered packages** always fail (NU3008), under every policy.
7. **Timing:** ≈7–9 ms per nuget.org package when warm, ≈1 ms for a small package, 120–220 ms for the first verification in a process (JIT, bundle load, CRL fetch).

## Q1. Which API verifies a signature? What does `dotnet nuget verify` use?

`dotnet nuget verify` (`VerifyCommandRunner`) and restore's package extraction both build a `PackageSignatureVerifier` with:
- `IntegrityVerificationProvider`: content unchanged since signing (NU3008).
- `SignatureTrustAndValidityVerificationProvider(allowUntrustedRootList)`: cert validity, chain trust, timestamps, revocation (NU3018/NU3028/NU3037…).
- `AllowListVerificationProvider(allowList, requireNonEmptyAllowList, …)`: author/repository cert fingerprint (+ owners) match (NU3034).

`ClientPolicyContext.GetClientPolicy(ISettings, ILogger)` is restore's way to turn nuget.config (`signatureValidationMode`, `<trustedSigners>`) into settings plus an allow-list. NuGet's built-in settings factories (`results/defaults.txt`):
```
GetAcceptModeDefaultPolicy     unsigned=True  illegal=True  untrusted=True  noTimestamp=True unknownRevocation=True reportUnknownRev=False ... revocation=Online
GetRequireModeDefaultPolicy    unsigned=False illegal=False untrusted=False noTimestamp=True unknownRevocation=True reportUnknownRev=True  ... revocation=Online
GetVerifyCommandDefaultPolicy  unsigned=False illegal=False untrusted=False noTimestamp=True unknownRevocation=True reportUnknownRev=True  counter=IfExists revocation=Online
```

Working code (`Verifier/Program.cs`, `PolicyVerifier`, trimmed):
```csharp
var settings = new SignedPackageVerifierSettings(
    allowUnsigned: !policy.RequireSignedPackages,
    allowIllegal: false,
    allowUntrusted: !policy.RequireSignedPackages && policy.AllowedSigners.Count == 0, // "accept" mode
    allowIgnoreTimestamp: true, allowMultipleTimestamps: true, allowNoTimestamp: true,
    allowUnknownRevocation: true, reportUnknownRevocation: true,
    verificationTarget: VerificationTarget.All,
    signaturePlacement: SignaturePlacement.Any,
    repositoryCountersignatureVerificationBehavior: SignatureVerificationBehavior.IfExistsAndIsNecessary,
    revocationMode: policy.Revocation == RevocationCheck.Online ? RevocationMode.Online : RevocationMode.Offline);

var allowList = policy.AllowedSigners.Select(s => (VerificationAllowListEntry)new TrustedSignerAllowListEntry(
    target:    s.Kind == SignerKind.Author ? VerificationTarget.Author : VerificationTarget.Repository,
    placement: s.Kind == SignerKind.Author ? SignaturePlacement.PrimarySignature : SignaturePlacement.Any,
    fingerprint: s.Sha256Fingerprint, algorithm: HashAlgorithmName.SHA256,
    allowUntrustedRoot: s.AllowUntrustedRoot, owners: s.Owners)).ToList();

var providers = new List<ISignatureVerificationProvider>
{
    new IntegrityVerificationProvider(),
    new SignatureTrustAndValidityVerificationProvider(policy.AllowedSigners.Where(s => s.AllowUntrustedRoot)
        .Select(s => new KeyValuePair<string, HashAlgorithmName>(s.Sha256Fingerprint, HashAlgorithmName.SHA256)).ToList()),
};
if (allowList.Count > 0)
    providers.Add(new AllowListVerificationProvider(allowList, requireNonEmptyAllowList: true,
        emptyListErrorMessage: "no allowed signers configured", noMatchErrorMessage: "package is not signed by an allowed signer"));

using var reader = new PackageArchiveReader(nupkgPath);
VerifySignaturesResult result = await new PackageSignatureVerifier(providers)
    .VerifySignaturesAsync(reader, settings, ct, Guid.Empty);
// result.IsValid, result.IsSigned, result.Results[*].Trust, result.Results[*].Issues (Code, Level, Message)
```
Inspecting signatures (`Verifier inspect`):
- `reader.GetPrimarySignatureAsync()` → `.Type`, `.SignerInfo.Certificate`, `.Timestamps`.
- `RepositoryCountersignature.GetRepositoryCountersignature(primary)` / `IRepositorySignature` → `PackageOwners`, `V3ServiceIndexUrl`.

API gotchas observed:
- **Rely on `IsValid`, not on error-level issues.** In accept mode, nuget.org packages came back `IsValid=true` while still logging NU3028 at *Error* level (`results/matrix-plain-sdk-nobundle-online.txt`). Conversely, `RevocationMode.Offline` + `allowUnknownRevocation=false` gave `IsValid=false` with **no error or warning**; only `Trust=Disallowed` explained it (`results/strict-revocation-offline.txt`). The library must produce its own reason text.
- `NuGet.Packaging 7.3.1` → `System.Security.Cryptography.Pkcs 8.0.1` triggers NU1902/NU1903 (known vulnerabilities). Pinning 10.0.7 still warned; **10.0.13 cleared it.**

## Q2. nuget.org on Linux? Which trust store? Fallback bundle? Without the SDK?

`X509TrustStore` (static, process-global) picks a chain factory per purpose (code signing / timestamping):

| How the app is set up | Factory | NuGet log line |
|---|---|---|
| Nothing called (plain library use) | `DotNetDefaultTrustStoreX509ChainFactory` | "will use the default trust store selected by .NET for code signing" |
| `X509TrustStore.InitializeForDotNetSdk(logger)` + `trustedroots/*.pem` next to `NuGet.Packaging.dll` | fallback bundle | "will use the fallback certificate bundle at '…/out/bundled/trustedroots/codesignctl.pem'" |
| `InitializeForDotNetSdk`, no bundle | none | "will not have any trusted roots. Chain building will fail with an untrusted status." |

- The DLL also contains the Fedora/RHEL probe path `/etc/pki/ca-trust/extracted/pem/objsign-ca-bundle.pem`; that file is absent on Ubuntu, so it couldn't be exercised.
- `InitializeForDotNetSdk(ILogger)` is the only public knob. `SetCodeSigningX509ChainFactory`, `CreateX509ChainFactoryForDotNetSdk(…, FileInfo)` and `IX509ChainFactory` are **internal**, so there's no supported way to pass our own bundle path or extra roots.
- The NuGet.Packaging nupkg doesn't contain the `.pem` files. They ship only in the .NET SDK (`sdk/<ver>/trustedroots/`: 307 code-signing roots, 327 timestamping roots).

Policy P1 ("require signed, any trusted signer"):

| Package | Default .NET store | Init, no bundle | Init + bundle next to DLL |
|---|---|---|---|
| Newtonsoft.Json (author+repo) | REJECT NU3018 | REJECT | **ACCEPT** |
| Humanizer.Core (author+repo, Symantec TSA) | REJECT NU3018, NU3028, NU3037 | REJECT | **ACCEPT** |
| Serilog (repo, 2024 cert) | ACCEPT | REJECT | **ACCEPT** |
| Dapper (repo, 2021 cert) | REJECT NU3018 | REJECT | **ACCEPT** |
| unsigned | REJECT NU3004 | REJECT | REJECT NU3004 |
| tampered | REJECT NU3008 | REJECT | REJECT NU3008 |

Copying the bundle next to the DLL *without* calling `InitializeForDotNetSdk` changes nothing (`results/matrix-bundled-default-online.txt`).

**Conclusion:** Linux needs the bundle **and** the `InitializeForDotNetSdk` call. NuGet never looks in the installed SDK, only next to *our* copy of `NuGet.Packaging.dll`, so the library or app must ship `codesignctl.pem` and `timestampctl.pem`. The spike does this with a `None` item (`Link="trustedroots/%(Filename)%(Extension)"`) copied from `$(NetCoreRoot)sdk/$(NETCoreSdkVersion)/trustedroots/` (`-p:BundleTrustedRoots=true`).

**Single-file publish:** `InitializeForDotNetSdk` throws:
```
System.ArgumentException: The value cannot be an empty string. (Parameter 'path')
   at NuGet.Packaging.Signing.FallbackCertificateBundleX509ChainFactory.GetThisAssemblyDirectoryPath()
   at NuGet.Packaging.Signing.X509TrustStore.InitializeForDotNetSdk(ILogger logger)
```
Workaround, verified in `results/singlefile.txt`: a target setting `ExcludeFromSingleFile="true"` on `NuGet.Packaging.dll` (`-p:KeepNuGetPackagingOnDisk=true`). All verdicts then match the normal build.

## Q3. Self-signed author certificate, allow-listed by SHA-256, no store install?

Yes (`results/matrix-bundled-sdk-online.txt`):

| Policy | self-signed, allow-listed | self-signed, other cert | tampered self-signed |
|---|---|---|---|
| P1 require signed, no allow-list | REJECT NU3018 | REJECT NU3018 | REJECT NU3008 |
| P2 `{Author, fp, AllowUntrustedRoot=true}` | **ACCEPT** (warn NU3027 no timestamp) | REJECT NU3018+NU3034 | REJECT NU3008 |
| P3 `{Author, fp}` without AllowUntrustedRoot | REJECT NU3018 | REJECT | REJECT |

- The fingerprint must be passed in **both** places: the allow-list entries and the `SignatureTrustAndValidityVerificationProvider` constructor. `ClientPolicyContext` does the same.
- Nothing was installed anywhere; verification needs only the fingerprint string.
- The test packages aren't timestamped (no TSA available offline). Without a timestamp, the signature becomes invalid when the cert expires, so plugin authors should use `--timestamper`.

## Q4. Expressing allowed signers; reusing NuGet's `trustedSigners`

NuGet's model:
- `<author>`: cert fingerprints (`hashAlgorithm`, `allowUntrustedRoot`). Matches the author primary signature only.
- `<repository serviceIndex>`: cert fingerprints + optional `<owners>a;b</owners>`. Matches a repository primary or countersignature; with owners, the signed owner list must include at least one of them.
- `signatureValidationMode` = accept | require.

Loading it with `ClientPolicyContext.GetClientPolicy` and verifying (`results/nugetconfig-trustedsigners.txt`):
```
policy=Require allowList=3
  target=Author placement=PrimarySignature fp=1EEBEA645B50BBAC... untrustedRoot=True owners=[]
  target=Repository placement=Any fp=5A2901D6ADA3D182... untrustedRoot=False owners=[jamesnk,serilog]
  target=Repository placement=Any fp=1F4B311D9ACC115C... untrustedRoot=False owners=[jamesnk,serilog]
  downloaded/newtonsoft.json.13.0.3.nupkg                 ACCEPT
  downloaded/humanizer.core.2.14.1.nupkg                  REJECT NU3034
  downloaded/serilog.4.0.0.nupkg                          ACCEPT
  feed/signed-selfsigned/Spike.SamplePlugin.1.0.0.nupkg   ACCEPT
  feed/signed-other/Spike.SamplePlugin.1.0.0.nupkg        REJECT NU3018; NU3034
  feed/unsigned/Spike.SamplePlugin.1.0.0.nupkg            REJECT NU3004
```
Our own policy objects give the same results: P4 (nuget.org, any owner), P5 (owners `[jamesnk, serilog]`: Newtonsoft and Serilog accepted, Humanizer and Dapper NU3034), P6 (Json.NET author cert only accepts Newtonsoft).

**Recommendation:** reuse the model and `TrustedSignerAllowListEntry`, but take configuration from our JSON options (ADR 0013), not nuget.config. A `FromNuGetConfig` helper could come later.

Practical points:
- **nuget.org has three repository certs** (2018, 2021, 2024; `https://api.nuget.org/v3-index/repository-signatures/5.0.0/index.json`): Dapper uses the 2021 cert, Serilog the 2024 one. Offer `AllowedSigner.NuGetOrg(owners)` expanding to the known certs, optionally refreshed from the feed's `RepositorySignatures` resource at resolution time.
- Fingerprints are of the **leaf** cert, so they change when an author renews. (Json.NET's cert expired 2024-10-29; its packages stay valid through their timestamps.)

## Q5. Timestamps and revocation offline

Method:
- `unshare -rn` gives a real no-network namespace without sudo.
- Each run uses a fresh `HOME`, so .NET's CRL cache (`~/.dotnet/corefx/cryptography/crls`) starts cold.
- The spike's suggested unreachable `HTTP(S)_PROXY` was also run.
- `tools/blackhole.py` is a proxy that accepts connections and never answers.

| Scenario | Verdicts (72 package×policy cells) | Notes |
|---|---|---|
| online, cold cache | baseline (25 ACCEPT) | no revocation warnings |
| no network, Online, cold cache | identical | NU3018 warnings "revocation server could not be reached" / "RevocationStatusUnknown" |
| no network, Online, warm cache | identical | no warnings |
| no network, **Offline** | identical | no warnings |
| refused proxy, Online | identical | same warnings; .NET honours `HTTP_PROXY` for CRL fetches |
| no network, Online, `allowUnknownRevocation=false` | REJECT NU3018 revocation unknown | |
| no network, Offline, `allowUnknownRevocation=false` | **REJECT, no message** | `Trust=Disallowed` only |
| **hanging network**, Online | ACCEPT but **120 s per package, every time** (3/3) | `results/timing-hanging-network-manual.txt` |
| hanging network, Online, 5 s CancellationToken | **not cancelled**: 120 s, normal result returned | `results/timing-hanging-network-cancel.txt` |
| hanging network, **Offline** | ACCEPT, 136 ms first / 6 ms warm | |

- **Revocation through the API:** `new SignedPackageVerifierSettings(..., revocationMode: RevocationMode.Offline)`. `NUGET_CERT_REVOCATION_MODE=offline` only affects the `Get*Policy()` factories (all four switched to Offline). Passing the value in the constructor ignores the env var, which suits ADR 0013.
- `RevocationMode` has only Online and Offline. `Offline` + `allowUnknownRevocation=true` is effectively "best effort, never touches the network".
- **Timestamps** verify fine offline against `timestampctl.pem`. Humanizer's countersignature uses a Symantec TSA: NU3028 with the default Linux store, OK with the bundle.
- Expired signing certs (all nuget.org samples) are accepted thanks to their timestamps; without the bundle they show NU3037.

## Recommended `TrustPolicy` shape

```csharp
public sealed class TrustPolicy
{
    // Pre-download source check; unrelated to signatures. Empty = any configured feed.
    public IList<string> AllowedFeeds { get; init; } = [];

    // false: unsigned packages allowed. Packages that ARE signed are still integrity-checked (NU3008 always fails);
    //        with AllowedSigners also empty, chain trust is not enforced (NuGet "accept" mode).
    // true:  every package (plugin AND dependencies) must have a valid signature chaining to a trusted root
    //        (bundled roots), or match an AllowedSigner with AllowUntrustedRoot.
    public bool RequireSignedPackages { get; init; }

    // Empty: any trusted signer. Non-empty: every SIGNED package must match >= 1 entry (author primary signature,
    // or repository primary/countersignature [+ owners]). Unsigned packages are governed only by RequireSignedPackages.
    public IList<AllowedSigner> AllowedSigners { get; init; } = [];

    // Online (default, as NuGet): CRL/OCSP; unknown status = warning, never failure. A hanging network = ~120 s/package.
    // Offline: cached CRLs only, never touches the network.
    public RevocationCheck Revocation { get; init; } = RevocationCheck.Online;
}

public sealed record AllowedSigner
{
    public SignerKind Kind { get; init; }              // Author | Repository
    public string Fingerprint { get; init; } = "";     // SHA-256 hex of the leaf signing certificate
    public IList<string> Owners { get; init; } = [];   // Repository only: package must list >= 1 of these owners
    public bool AllowUntrustedRoot { get; init; }      // self-signed / private CA, no store changes
    public string? Name { get; init; }                 // display only
    public static IEnumerable<AllowedSigner> NuGetOrg(params string[] owners); // expands to nuget.org's repo certs
}
```

The exact mapping onto NuGet is the Q1 snippet. Deliberately **not** exposed:
- `allowIllegal`: always false.
- Timestamp knobs: always NuGet's require-mode values.
- Strict revocation: it breaks offline machines and fails silently in Offline mode. Could be added later as `Revocation = OnlineStrict`.

Verification runs on the `.nupkg` after download and before extraction (install, update, restore). Startup validation stays local (ADR 0010 hash pinning). `VerifyAsync()` could optionally re-verify the kept `.nupkg` files.

## Linux vs Windows vs needs-SDK

| | Linux (verified) | Windows (not run) | Needs SDK? |
|---|---|---|---|
| Integrity / tamper (NU3008) | works | same managed code | no |
| Unsigned detection (NU3004) | works | same | no |
| Self-signed + fingerprint + AllowUntrustedRoot | works | same managed code, expected to work | no |
| Owners / repository allow-list | works | same | no |
| Chain trust for nuget.org / public CAs | **only with shipped `trustedroots/*.pem` + `InitializeForDotNetSdk`**; the default store rejects 3/4 | default factory = Windows cert store (code-signing roots + auto root update), expected to work without a bundle. **Unverified.** With Init + bundle, Windows uses the same code path | the `.pem` files *come from* the SDK, but the SDK is **not needed at runtime** if we ship them |
| Single-file publish | needs `NuGet.Packaging.dll` excluded from the bundle | same (`Assembly.Location` is empty) | no |
| `dotnet nuget sign` (plugin developers) | self-signed works (warnings); private CA fails (PartialChain) | not tested | yes (build time only) |
| macOS | not tested | | |

Recommendation: **always** call `InitializeForDotNetSdk` and ship the bundle on every OS. That gives identical behaviour everywhere and no dependency on the machine's store. It's process-global, and the first caller wins. A quick Windows confirmation run is still needed.

## Impact on the plan / ADRs

1. **ADR 0010:** add these consequences:
   - Verification uses `PackageSignatureVerifier`.
   - The library ships the code-signing/timestamping root bundle (from the SDK's `trustedroots/`) and must refresh it with SDK/NuGet updates.
   - NuGet's trust-store selection is **process-global**, a documented exception to ADR 0012.
   - Single-file apps must keep `NuGet.Packaging.dll` on disk (provide build targets).
2. **architecture.md §12:** replace "allowed signer certificates / package owners" with the precise model:
   - Author fingerprint, or repository fingerprint + owners, each with `AllowUntrustedRoot`.
   - `Revocation` Online/Offline.
   - Signed packages are always integrity-checked.
   - `AllowedFeeds` is a pre-download check.
   - `NuGetOrg(...)` exists because nuget.org repository certs rotate.
3. **CONTEXT.md "Trust policy":** allowed signers = author certificate fingerprints, or repository certificate + owners.
4. **implementation-plan.md:**
   - Align the trust policy on **Phase 4**, since it runs at download time. (The spike table said Phase 5.)
   - Add tasks:
     - bundle the `.pem` files with `buildTransitive` targets (copy next to NuGet.Packaging.dll; `ExcludeFromSingleFile`);
     - pin `System.Security.Cryptography.Pkcs` ≥ 10.0.13;
     - map NU30xx codes and `Trust` statuses to our own failure reasons;
     - a Windows confirmation run of `Verifier matrix`;
     - integration tests reusing these fixtures.
   - Replace the risk row "Signature verification is platform dependent" with: "Linux needs the shipped root bundle (solved); online revocation on a hanging network costs ~120 s per package and isn't cancellable (mitigate: `Revocation=Offline`, document)".
5. **App developer guide:** default `Revocation=Online` (NuGet's default). Document the hanging-network cost and recommend Offline for air-gapped or industrial hosts. *(Open question: should the default be Offline?)*
6. **Plugin developer guide:** sign with `dotnet nuget sign --timestamper <url>`. Self-signed certs are fine for private distribution; the app allow-lists the fingerprint with `AllowUntrustedRoot`.

```bash
./setup.sh                   # certs (openssl, files only), pack/sign/tamper, download nuget.org packages

```
