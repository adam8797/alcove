# Context

Shared vocabulary for this project. Use these terms in code, docs and discussion. If a term needs to change, change it here first.

> Project name: **Alcove**, a sheltered recess (and a nod to **ALC**, `AssemblyLoadContext`). Each plugin lives in a **cell**.

## People

| Term | Meaning |
|---|---|
| **App developer** | Writes the host app that loads plugins. Decides where plugins live, which feeds are used, and who may manage plugins. |
| **Plugin developer** | Writes a plugin and publishes it as a NuGet package. |
| **Operator / user** | Whoever manages plugins at runtime. The library has no say in who that is; the host app decides. |

## Core concepts

| Term | Meaning |
|---|---|
| **Host / host app** | The application (console, WPF, web, ...) that uses this library to load plugins. |
| **Plugin** | One installed NuGet package and its code. A plugin provides zero or more extensions. |
| **Extension** | A single object a plugin contributes, e.g. one tool window or one command. |
| **Extension point** | A type, usually an interface defined in the host's contracts package, that extensions implement (e.g. `IToolWindow`). |
| **Contracts package** | A NuGet package published by the host that defines its extension points. A plugin's dependency version range on it decides whether the plugin is compatible with a given host version. |
| **Cell** | A group of one or more plugins that share one `AssemblyLoadContext`. Each cell holds exactly one version of any given assembly. |
| **Catalog** (`ExtensionCatalog`) | The registry the host queries for every extension of a type `T` across all loaded plugins. Raises events when extensions are added, e.g. by a hot install. |
| **Plugin root** | The directory where installed plugins and library state live. Always supplied by the app developer; the library never picks a default. |

## Packages and files

| Term | Meaning |
|---|---|
| **Plugin package** | A NuGet package marked with a custom `PackageType` (used for discovery) and containing a plugin manifest. |
| **Plugin dependency** | A `.nuspec` dependency on another plugin package. That package is installed and loaded as a plugin, before the plugin that depends on it. |
| **Plugin manifest** | A file inside the plugin package holding what the `.nuspec` can't: cell request, isolated flag, cell-private dependencies, entry point. Generated by the plugin SDK. Display metadata (name, description, icon, authors) comes from the `.nuspec`, never the manifest. |
| **Configuration file** | An optional JSON file (System.Text.Json) holding serialisable `PluginHostOptions`: feeds, cells, trust policy and so on. The library only reads it when the app calls `PluginHostOptions.Load`. |
| **Options** (`PluginHostOptions`) | The configuration. Whatever object the app passes to `PluginHost.Create` is final. The app may load it from the file, load and modify it, or build it in code. The library never merges sources. |
| **State file** | A file in the plugin root that only the library writes: installed plugins, exact versions, package hashes, resolved dependencies, staged updates and uninstalls. |
| **Trust policy** | Optional settings from the app: allowed feeds (checked before download), required signatures, allowed signers (an author certificate fingerprint, or a repository certificate + package owners, each optionally allowing an untrusted root), and revocation mode (Online/Offline). Signed packages are always integrity-checked. Hash pinning (`contentHash`) in the state file is always on. Plugins always run with full trust. |

## Plugin-facing API

| Term | Meaning |
|---|---|
| **Abstractions package** | `Alcove.Abstractions`: the small, rarely changing package plugins reference (`IPlugin`, `IPluginContext`, attributes). Depends only on `NuGet.Versioning` and `Microsoft.Extensions.Logging.Abstractions` (lowest supported version). Backward compatible within a major version. The manifest records its schema version. |
| **Entry point** (`IPlugin`) | Optional. Registers extensions synchronously, with an optional async initialize step. Named by the manifest, or discovered when the plugin has exactly one public, non-abstract `IPlugin` class. A plugin without one is scanned for `[Extension]`-attributed types only. |
| **Plugin context** (`IPluginContext`) | What a plugin receives: its ID and version, a private data directory, a logger, and the host's services. |
| **Extension lifetime** | Chosen by each registration: `Singleton` (default, one shared instance) or `Transient` (new instance per request). |
| **Extension metadata** | Data registered with an extension that can be read without creating it (`Lazy<T, TMetadata>` style). |
| **Plugin SDK** | `Alcove.Sdk`, an ordinary NuGet package with props/targets. Sets the `PackageType`, generates the manifest from MSBuild properties (also into the build output), and keeps contracts referenced but not bundled. Also provides the harness helpers (`PluginUnderTest`, `AlcoveHarnessExecutable`). |

## Development

| Term | Meaning |
|---|---|
| **Development plugin** (`DevelopmentPlugin`) | A plugin loaded from its build output folder instead of the plugin root, for the plugin developer's inner loop ([ADR 0017](docs/adr/0017-development-plugins.md)). Classified from its `deps.json` and validated like an installed plugin, loaded in place, in its own cell. Not installed, never recorded in the state file, not trust-verified, never cleaned up. Wins over an installed plugin with the same ID for that run. `PluginInfo.IsDevelopment`. Only loaded when the app adds it to `PluginHostOptions.DevelopmentPlugins`. |
| **Harness** | A program, provided by the app developer, that starts the app (or a stand-in host) with development plugins enabled, usually through `AddDevelopmentPluginsFrom(args, env)`. Style 1: a harness project the plugin developer adds; style 2: F5 on the plugin's class library, through `AlcoveHarnessExecutable`. |
| **Plugin under test** (`PluginUnderTest`) | A plugin project a harness project names: built first, never referenced or copied into the harness, and recorded in a generated `[assembly: AlcoveDevelopmentPlugin(...)]`. |

## Dependency injection (add-ons)

| Term | Meaning |
|---|---|
| **Activator** (`IExtensionActivator`) | Creates extension instances. The core default uses factories / parameterless constructors; DI add-ons replace it. |
| **Cell service provider** | With a DI add-on, each cell gets one service provider holding its plugins' registrations, falling back to the host's provider. Disposed in reverse load order. |
| **Service plugin** (`IServicePlugin`) | A plugin that registers services into its cell's provider. Defined in each DI add-on (`Alcove.DependencyInjection`, `Alcove.Autofac`). |

Extensions are always obtained from the catalog, never from the root container's `IEnumerable<T>`.

## UI add-ons

| Term | Meaning |
|---|---|
| **Cell observer** (`ICellObserver`) | An object told by one host when a cell is created (`CellCreated`), when a hot install adds private assemblies to an existing cell (`CellExtended`), and when a plugin's assemblies are loaded, before it registers (`PluginLoading`). Created per host from the factories in `PluginHostOptions.CellObservers`, and disposed with the host. It's the core's only hook for UI frameworks; `Alcove.Wpf` uses it for pre-loading, the forwarder and resource merging. |
| **Pre-loading** | `Alcove.Wpf` loading a cell's WPF-relevant private assemblies as soon as the cell exists, because WPF only finds assemblies that are already loaded. |
| **Default-context forwarder** | `Alcove.Wpf`'s opt-in `AssemblyLoadContext.Default.Resolving` handler. It sends WPF's failed default-context loads to the single cell owning a private copy of that name. Process-wide while its host lives ([ADR 0012](docs/adr/0012-app-supplies-root-no-global-state.md)). |
| **Shared resource key** (`SharedResourceKey<T>`) | A typed WPF resource key that the app defines once in its host-owned contracts package or app SDK, so the app and every plugin use the same key. |

## Cells

| Term | Meaning |
|---|---|
| **Committed answers** | For each cell, the planned answer for every assembly its plugins need, plus the first answer `Load` actually gave for any name. Once given, an answer is frozen. A hot install that would need a different answer for a committed name becomes *pending restart*. |
| **Default cell** | Unless something says otherwise, each plugin gets its own cell. |
| **Named / shared cell** | A cell holding several plugins. It can be defined in the app's options, or requested by a plugin ("put me in cell `X`"). If they disagree, the app's options win. |
| **Isolated plugin** | A plugin flagged to require a cell to itself. Adding any other plugin to that cell fails validation, even when the app's options do it. |
| **Host-owned assembly** | An assembly the app declares as its own, such as its contracts package or an app SDK (e.g. `MyApp.Sdk` with UserControls and helpers). Always host-owned as well: the .NET shared frameworks, `Alcove.Abstractions`, `NuGet.Versioning` and `Microsoft.Extensions.Logging.Abstractions`. A dependency of a host-owned package is host-owned too (e.g. `Microsoft.Extensions.DependencyInjection.Abstractions`). Always loaded from the host's (default) context and never made cell-private. If a plugin needs a version the host doesn't have, the plugin is incompatible. |
| **Host inventory** | What the host provides, read at startup from its `deps.json` files (`APP_CONTEXT_DEPS_FILES`) and its entry assembly's framework attributes. Framework-provided packages are skipped, not version-checked. Single-file hosts have no inventory and are unsupported in v1. |
| **Exposed dependency** | A dependency whose types appear in a plugin's public API, found by a metadata scan at install. Every cell that uses the plugin must get it through that plugin's cell; if a consumer needs an incompatible version, validation reports `ExposedDependencyConflict`. |
| **WPF-relevant assembly** | An assembly containing `<AssemblyName>.g.resources` (compiled XAML), or referenced by one that does (through its AssemblyRef table or the assembly names in its BAML). WPF resolves these by name across the whole process, so duplicates in different cells are detected and reported. |
| **Host-shared assembly** | An assembly the host already provides (from its `deps.json`). Plugins use the host's copy by default. |
| **Cell-private assembly** | An assembly loaded inside a cell instead of using the host's copy. This happens either because of a version conflict with the host, or because the plugin developer marked the dependency as private. There is no per-plugin privacy; the finest level is the cell. |

## Lifecycle

| Term | Meaning |
|---|---|
| **Install** | Add a plugin and its dependencies. Takes effect immediately (hot). |
| **Update / uninstall** | Staged now, applied at the next host startup. Updating one plugin in a shared cell reloads the whole cell at that restart. |
| **Staged change** | An update, uninstall, enable or disable recorded in the state file and applied at next startup, before anything loads. An update downloads the new version next to the old one. |
| **Pending changes** | The difference between what's loaded in this process and the state file on disk, e.g. after another instance installed something. The app can query it and list what will change at restart. |
| **Rollback** | Called by the app (`RollbackAsync(pluginId)`) to switch back to a previous version kept on disk. Never automatic. |
| **Restore** | `RestoreAsync()` downloads everything the state file pins (exact versions and hashes), e.g. on a fresh machine. |
| **Root lock** | A lock file (`<root>/.lock`) held while changing the state file. `LoadAsync` takes it only briefly, to apply staged changes and write its in-use record; if another process holds it past the timeout, loading goes ahead and the staged changes wait for a later start. |
| **In-use record** | A file per running `PluginHost` in `<root>/.inuse/` listing the package folders it loads from. Startup cleanup never deletes a folder a live record lists. |
| **Kept version** | A previous version left on disk for rollback (`PluginHostOptions.VersionsToKeep`, default 1). |
| **Pending restart** | Status of a hot install that can't load into the running process, with a reason (e.g. the conflicting assembly names). It loads at next startup. |
| **Enable / disable** | A disabled plugin stays installed but isn't loaded. Takes effect at restart only. |
| **Faulted** | A plugin that threw during load, entry-point setup or extension creation. The library records the exception, raises an event and keeps loading the others. It never disables a plugin on its own; that is the app's decision. A fail-fast switch exists for development. |
| **Validation** | Always runs before loading. It is local and doesn't use the network: state file vs. disk (file sizes and timestamps; full SHA-512 re-hash on demand with `VerifyAsync`), manifests and their schema version, host compatibility (`HostOwnedConflict`), cell rules, the plugin dependency graph, entry points (`EntryPointAmbiguous`), exposed-dependency conflicts, WPF duplicates and native library collisions. Results are a `ValidationReport` with codes from `ValidationCodes`. |
| **Resolution** | Fetching and resolving packages from NuGet feeds. Optional at startup; the app developer chooses whether to call it before loading. |
